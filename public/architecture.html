Field notes · Sept 2026

Three ways onto HarmonyOS.

Every mature codebase hits a different wall on HarmonyOS NEXT — a missing GMS plugin, a C engine with no ArkUI face, or a closed protocol. Pick the seam that fits the wall. Each pattern below ships in one of the ports.

01 · Shim

The Flutter backport shim

Keep the Dart. Replace the platform side.

A Flutter app that depends on google_maps_flutter won’t compile for OpenHarmony — there is no GMS binary on-device. Instead of rewriting the UI in ArkTS, OpenGMaps adds google_maps_flutter_ohos: a plugin that honours the stock Dart interface and translates calls to JSON for an ArkWeb view running Maps JS API 3.56. GPS comes from Location Kit over a narrow native channel.

When to use it

  • Screens, state and models in Dart are worth keeping as-is.
  • The missing piece is one or two platform plugins, not the whole app.
  • You can live with a WebView for one surface (here: the map).

02 · Shell

ArkTS shell + NAPI bridge

Give a C engine a HarmonyOS window.

GNU Emacs is thirty years of C. OHEmacs doesn’t port the editor — it houses it. A Stage-model HAP owns the window, mounts an XComponent EGL surface for GPU rendering, and runs a small NAPI module (libentry.so) that ferries touch, key and resize events into the upstream engine. The Lisp VM runs on-device after a two-stage pdump cross-compile.

When to use it

  • The engine is C/C++ and too large to rewrite (editors, emulators, renderers).
  • You need GPU output with no canvas copies — EGL straight to the surface.
  • A CLI fallback is useful: the same tree builds a native emacs binary.

03 · Server

Companion server

Keep the protocol off the phone.

WhatsApp has no HarmonyOS SDK, and re-implementing its encryption in ArkTS would be fragile. WhatIsIt splits the problem: a Go daemon (server-go, on whatsmeow) owns the Multi-Device session, SQLite store and keepalive; the phone runs a thin ArkTS client that syncs over HTTP and WebSocket push. Pair once with QR or an 8-character code.

When to use it

  • The protocol is closed, stateful, or crypto-heavy.
  • You want the phone process to stay small and battery-light.
  • Sessions must survive kills, reboots and sleep.
